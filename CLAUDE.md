# CLAUDE.md - Инструкции для Claude Code

## 🎯 Общие принципы работы

1. **Всегда создавай новую ветку** перед внесением изменений (формат: `feature/краткое-описание` или `fix/краткое-описание`).
2. **Перед отправкой изменений** всегда запускай проверки: `npm run lint` и `npm run type-check`.
3. **Коммиты** пиши на английском в формате Conventional Commits: `feat: add user authentication`, `fix: resolve login error`, `refactor: simplify api client`.
4. **Не изменяй файлы в папках** `.next/`, `node_modules/`, `dist/`, `build/` — они генерируются автоматически.
5. **Если сомневаешься** — спрашивай у пользователя, а не делай предположений.

## 📁 Структура проекта
src/
├── app/ # Next.js App Router (страницы и API-роуты)
├── components/ # Переиспользуемые UI-компоненты
│ ├── ui/ # Базовые компоненты (кнопки, инпуты)
│ └── features/ # Компоненты для конкретных функций
├── lib/ # Утилиты, конфиги, клиенты API
├── hooks/ # Кастомные React-хуки
├── types/ # TypeScript-типы и интерфейсы
└── styles/ # Глобальные стили и Tailwind-конфигурация


## 🧪 Тестирование

- Используем **Jest + React Testing Library**.
- Для каждого компонента пишем хотя бы один базовый тест (`render` и `snapshot`).
- Критические пути (логин, оплата, создание заказа) должны покрываться интеграционными тестами.
- Запуск тестов: `npm test`, для coverage: `npm test -- --coverage`.

## 🌐 API и работа с данными

- Все запросы к API идём через **React Query** (`@tanstack/react-query`).
- Храним кэш в `lib/queryClient.ts`.
- Для мутаций обязательно используем `useMutation` с обработкой ошибок (`onError`).
- Эндпоинты выносим в константы в `lib/api/endpoints.ts`.

## 🎨 Стилизация и UI

- Используем **Tailwind CSS** — не пишем кастомный CSS без крайней необходимости.
- Цветовая схема: все цвета берём из `tailwind.config.js` (темная/светлая тема через CSS-переменные).
- Адаптивность: сначала мобильные устройства (Mobile First), используем брейкпоинты `sm`, `md`, `lg`, `xl`.
- Компоненты должны быть доступны (a11y): добавляем `aria-label`, `role`, управление фокусом.

## 🔒 Безопасность

- **Никогда** не хардкодим секреты, API-ключи, токены. Все переменные окружения через `.env.local` и `process.env.NEXT_PUBLIC_*`.
- Валидируем все входные данные на клиенте (Zod-схемы в `lib/validations/`).
- Защищаем API-роуты: проверяем JWT-токен через middleware в `src/middleware.ts`.

## 🚀 Деплой и CI/CD

- Деплой автоматический через **Vercel** при пуше в `main`.
- Стейжинг (staging) — ветка `develop`.
- PR в `main` должен проходить все проверки (linter, type-check, tests) и получать аппрув от как минимум одного ревьюера.
- Если CI упал — сначала исправь ошибки, потом запрашивай ревью.

## 📦 Управление зависимостями

- Добавляем только проверенные библиотеки. Перед установкой новой зависимости убедись, что она активно поддерживается и имеет хорошую документацию.
- Используем `npm` (не `yarn` или `pnpm`).
- Периодически обновляем зависимости через `npm outdated` и `npm update`.

## 🤖 Особенности работы Claude Code

1. **Максимальная длина файла** — 400 строк. Если файл больше, предложи его рефакторинг.
2. **Комментарии** пиши на английском, но понятным языком.
3. **Не удаляй существующий код** без явного разрешения — сначала предложи альтернативу.
4. **Если видишь дублирование кода** — выноси в утилиты или хуки.
5. **Для сложных задач** создай план и покажи его пользователю перед реализацией.

## 📋 Шаблон для новых фич

1. Создать ветку `feature/название-фичи`.
2. Написать тесты (если применимо).
3. Реализовать логику и UI.
4. Запустить `npm run lint` и `npm run type-check`.
5. Создать PR с описанием изменений.
6. Дождаться аппрува и успешного CI.
7. Замерджить в `develop` или `main`.
